🗂️ Claude Projects & Project Instructions

A Project is a persistent workspace in Claude where context, files, and instructions are maintained across all conversations. Instead of re-explaining your role, goals, and constraints every time, a Project remembers everything.

🗂️ What a Project Contains
1
Project Instructions

Your custom system prompt — who you are, how Claude should respond, what tone and format to use

2
Uploaded Files

Documents, code files, specs, data — Claude references these across every conversation in the project

3
Conversation History

All past chats within the project — Claude can refer back to earlier decisions and context

4
Persistent Memory

Claude remembers project-level facts so you never repeat yourself across sessions

Writing Effective Project Instructions

Project instructions are a one-time investment that multiplies every interaction. Poorly written instructions produce generic, off-target responses. Well-written ones turn Claude into a domain-specific expert that knows your context by default.

❌ Weak Instructions
  • You are a helpful assistant
  • Be professional and concise
  • Help me with my work tasks
  • Use bullet points where helpful
✓ Strong Instructions
  • Role, company context, and team stated
  • Explicit tone and output format rules
  • Constraints: audience, level of detail
  • What to always/never do specified
Engineering Project Instructions
You are a senior software engineering assistant for a fintech startup.

CONTEXT:
- Stack: Java 17, Spring Boot 3, PostgreSQL, Kafka, AWS (ECS/RDS)
- Team: 6 engineers, 2-week sprints, strict PR review culture
- Standards: RESTful APIs, OpenAPI 3 docs, 80%+ test coverage

MY ROLE: Senior backend engineer, 8 years experience

ALWAYS:
- Use modern Java idioms (records, streams, sealed classes)
- Include error handling and edge cases by default
- Flag performance issues and N+1 query risks proactively
- Structure code examples to be copy-paste ready

NEVER:
- Suggest deprecated Spring patterns
- Skip test coverage or security considerations
- Give vague "it depends" answers without a concrete recommendation

FORMAT: Code first, brief explanation after. Use inline comments.
Business Analyst Project Instructions
You are a business analysis partner for an enterprise SaaS company.

CONTEXT:
- Industry: B2B HR Technology
- Stakeholders: CPO, CFO, Head of Sales (non-technical)
- My deliverables: requirements docs, process maps, exec summaries

MY ROLE: Lead BA, bridging product and engineering

ALWAYS:
- Frame insights in business value and ROI terms
- Flag assumptions and open questions explicitly
- Structure documents for busy executives (key finding first)
- Use measurable success criteria, not vague goals

NEVER:
- Use jargon without defining it for a non-technical audience
- Leave requirements ambiguous — ask clarifying questions
- Skip the "so what?" — every data point needs a business implication

FORMAT: Use headings, executive summary at top, supporting detail below.
Research / Study Project Instructions
You are a research and study assistant for a postgraduate student in AI/ML.

CONTEXT:
- Field: Machine Learning — focus on LLMs and agentic systems
- Level: PhD Year 2 — comfortable with advanced maths and theory
- Goal: Preparing thesis on multi-agent reasoning systems

MY NEEDS: Literature synthesis, argument development, writing feedback

ALWAYS:
- Cite specific papers when making claims (author, year, venue)
- Flag when a statement is contested or lacks strong evidence
- Challenge weak arguments — don't just validate what I write
- Distinguish between established results and open research questions

NEVER:
- Oversimplify complex topics — I prefer precision over accessibility
- Present one perspective as settled when debate exists
- Skip limitations or failure cases

FORMAT: Academic tone, dense but clear. Use LaTeX notation for maths.
Content Creator Project Instructions
You are a content strategy and writing partner for a LinkedIn creator.

CONTEXT:
- Niche: AI for business professionals — practical, non-hype
- Audience: Mid-senior professionals (managers, founders, analysts)
- Platform: LinkedIn primary, email newsletter secondary
- Posting frequency: 3x/week LinkedIn, 1x/week newsletter

MY VOICE: Confident, direct, slightly contrarian. No fluff.

ALWAYS:
- Lead with a hook — first line must stop the scroll
- Use short paragraphs (1–3 lines) and white space
- Include one concrete, specific takeaway per post
- Make it immediately usable — not just interesting

NEVER:
- Generic motivational content or engagement bait
- "AI is changing everything" without specifics
- Lists longer than 5 items unless the format demands it

FORMAT: LinkedIn post format — no headers, short grafs, clear CTA.
🗂️ Exercise 1 — Build Your Own Project

Create a Project for Your Most Frequent Claude Use Case

  • In Claude.ai, create a new Project and name it after your primary use case
  • Write project instructions using the template above — fill in your role, context, always/never rules, and format preference
  • Upload 1–2 reference files: a recent doc, style guide, or spec your work references constantly
  • Run the same prompt you've used before — compare the response quality with and without the project context

The test: Could someone unfamiliar with your role read these instructions and understand exactly how to help you? If yes — they're good. The most powerful instruction isn't the role statement, it's the NEVER list. Constraints generate quality.

Iterate: After 5 conversations, ask Claude: "Based on these instructions, what's missing that would help you assist me better?" Claude will surface gaps you didn't notice.

🎨 Artifacts — Structured Outputs Inside Claude

An Artifact is a self-contained, rendered output that Claude generates alongside the conversation — a document, a code file, a diagram, a table — displayed separately so you can read, copy, or refine it independently of the chat thread.

Artifact TypeWhat It ProducesBest Used For
DocumentFormatted text, markdown, reportsBriefs, READMEs, specs, summaries
CodeRendered, syntax-highlighted codeScripts, functions, configs, migrations
SVG / DiagramVector graphics rendered inlineArchitecture diagrams, flowcharts, charts
React ComponentLive interactive UI previewMockups, dashboards, calculators
HTML PageRendered web pageReports, templates, landing page drafts
💡
When to Request an Artifact

Any time the output is a standalone deliverable — not a conversational answer. Ask explicitly: "Create this as an artifact." Claude will render it in the sidebar panel for easy copying and iteration.

Product Requirements Document
Create a Product Requirements Document as an artifact.

Feature: [Feature name and one-line description]
Context: [Product, user type, business goal]
Constraints: [Tech stack, timeline, team size]

Include these sections:
1. Problem Statement — what user pain does this solve?
2. Goals and Non-Goals — what we're building and explicitly NOT building
3. User Stories — 3–5 in "As a [user], I want [action] so that [benefit]" format
4. Functional Requirements — numbered, specific, testable
5. Non-Functional Requirements — performance, security, accessibility
6. Open Questions — decisions still needed

Format as a professional markdown document. Use headers and tables where appropriate.
System Architecture Diagram (SVG)
Create an SVG architecture diagram as an artifact.

System: [Name and brief description]
Components to include: [list your services, databases, queues, clients]
Key flows to show: [e.g. user request → API → service → DB → response]

Requirements:
- Clean, readable layout — boxes with labels, arrows for data flow
- Colour-code by layer: client (blue), backend (green), data (orange), external (grey)
- Label all connections with the protocol (REST, gRPC, Kafka, etc.)
- Include a simple legend

Make it suitable for a technical design review presentation.
Structured Comparison Table
Create a detailed comparison table as an artifact.

Items to compare: [List 3–5 tools, options, or approaches]
Evaluation dimensions: [List your 5–8 criteria]

For each cell:
- A 1–5 score
- A brief note (max 10 words) explaining the score

Add a final row: "Recommended for" — describing the ideal use case for each option.
Highlight the top overall performer in the header.

Make this export-ready — clean markdown table format.
Interactive UI Mockup (React)
Create an interactive React component as an artifact.

Component: [Name and purpose — e.g. "User Settings Panel"]
Layout: [Brief description — sidebar, modal, card, etc.]

Include these elements:
[List your UI elements: buttons, inputs, dropdowns, toggles]

Interactions to demonstrate:
[Describe 2–3 interactions — e.g. toggle, form submit, state change]

Style: Clean, professional — white background, subtle shadows, blue primary colour
State: Show realistic placeholder data
Size: Fits within a 800px wide panel

This is for stakeholder review — make it visually polished.

📄 Long Context & Multi-File Analysis

Claude's 200K token context window can hold roughly 150,000 words — about 500 pages of text. This unlocks workflows that were previously impossible: analysing entire codebases, synthesising multiple research papers, or reviewing full contracts simultaneously.

⚠️
The Common Mistake

Uploading a large file and asking "summarise this" wastes the context window. Be specific: tell Claude what to look for, what decisions you need to make, and what format you need the output in.

📄 Analysing a Single Large Document ▼
Deep Document Analysis
[Upload document]

I've uploaded: [document type — contract, report, codebase, paper]
My role: [who you are and your relationship to this document]
My decision: [what I need to decide or do based on this document]

Please analyse this document for:
1. KEY FINDINGS: Top 5 most important points for my decision
2. RISKS / RED FLAGS: Anything that requires my attention or carries risk
3. GAPS: What's missing that I'd normally expect in this type of document
4. OPEN QUESTIONS: What I should ask or clarify before proceeding
5. RECOMMENDATION: Your suggested next action based on the above

Don't summarise every section — focus on what matters for my decision.
📚 Synthesising Multiple Documents ▼
Multi-Document Synthesis
[Upload all documents]

I've uploaded [N] documents: [brief description of each — e.g. "3 vendor proposals", "5 research papers on X", "4 sprint retrospectives"]

SYNTHESIS TASK:
1. COMMON THEMES: What do all documents agree on?
2. KEY DIFFERENCES: Where do they diverge significantly?
3. GAPS: What important topic is missing across all documents?
4. CONTRADICTIONS: Any direct conflicts or inconsistencies between documents?
5. INTEGRATED INSIGHT: What single conclusion do all documents collectively point toward?

Label which document(s) support each point using: [Doc 1], [Doc 2], etc.
💻 Working with a Large Codebase ▼
Codebase Analysis
[Upload code files]

Codebase: [language, framework, approximate size]
My goal: [what I'm trying to do — debug, refactor, add feature, review, understand]

Please perform the following analysis:
1. ARCHITECTURE: Explain how the codebase is structured (components, layers, dependencies)
2. ENTRY POINTS: Where does execution begin? Trace the main flow.
3. PROBLEM AREAS: Anti-patterns, tech debt, or code smells worth addressing
4. RELEVANT SECTION: Which files/functions are most relevant to [my specific goal]?
5. RECOMMENDED APPROACH: Given my goal, what's the safest way to proceed?

Highlight line numbers when referencing specific code.
🔍 Extracting Structured Data from Documents ▼
Structured Data Extraction
[Upload documents]

Extract the following structured information from these documents:

FIELDS TO EXTRACT:
- [Field 1]: [what it is, where to find it]
- [Field 2]: [what it is, where to find it]
- [Field 3]: ...

OUTPUT FORMAT: A clean table with one row per document/record.
If a field is missing or ambiguous: mark as "—" and note "Source unclear".
Do not infer or guess — only extract what's explicitly stated.

After the table: flag any documents with incomplete or inconsistent data.
📄 Exercise 3 — Multi-File Analysis

Synthesise Multiple Documents in One Conversation

  • Upload 2–3 related documents to a Project: meeting notes, reports, specs, or papers
  • Run the Multi-Document Synthesis prompt — do the contradictions surprise you?
  • Follow up: "Based on all three documents, draft a 3-paragraph executive summary for a non-technical stakeholder."
  • Then: "Which document has the weakest evidence for its claims?"

The most powerful thing about Claude's long context isn't summarisation — it's cross-document reasoning. Ask Claude to find where two documents contradict each other, or what one document implies for a decision described in another. That's the analysis that used to take days of human reading time.

⚡ You Can Now…

  • Analyse 500-page documents with decision-focused, structured prompts
  • Synthesise multiple documents simultaneously — finding contradictions and gaps
  • Extract structured data tables from unstructured document sets

🔗 Structured Multi-Step Prompting

Complex professional outputs rarely come from a single prompt. Prompt chaining breaks a large deliverable into sequential steps, using each output as the input for the next — producing results that are far more structured, accurate, and professional than any single-shot prompt could achieve.

🔗 The Prompt Chaining Pattern
1
Define the Final Deliverable

Tell Claude the end goal before starting — it shapes how it approaches every step

2
Break Into Logical Stages

Research → Structure → Draft → Refine → Format — each stage builds on the last

3
Validate Before Advancing

After each step, review and adjust — correct errors early, not at the end

4
Stay in One Conversation

Claude maintains all context — no need to re-explain your requirements at each step

5
Request the Final Assembly

Ask Claude to combine all steps into the polished final artifact

Example Chain: Strategy Report

Here's how a full chained workflow looks in practice — each message builds on the previous response:

1
Step 1 — Frame the Problem "I need to write a competitive analysis report for [product]. Our top 3 competitors are [A, B, C]. My audience is the CPO and CFO. Don't write anything yet — confirm you understand the task and what you'll need."
2
Step 2 — Analyse Each Competitor "Now analyse Competitor A. Focus on: pricing model, key differentiators, known weaknesses, and where they win/lose against us. Be specific — not generic industry observations."
3
Step 3 — Synthesise Across Competitors "Based on all three analyses: what are the top 3 strategic threats and 3 strategic opportunities for our product? Rank by urgency."
4
Step 4 — Draft Recommendations "Now write 4 concrete strategic recommendations for the CPO based on this analysis. Each must be specific, actionable within 90 days, and tied to a competitive insight."
5
Step 5 — Assemble Final Report "Assemble everything into a polished competitive analysis report as an artifact. Include: Executive Summary, Competitor Analyses, Strategic Synthesis, and Recommendations. Executive-level formatting."
Step 1 of 4 — Technical Design Chain
I need to produce a Technical Design Document for: [feature/system name]
Context: [stack, team, scale, key constraints]
Audience: Engineering team leads and principal engineers

Step 1 — REQUIREMENTS CAPTURE
Extract and list:
- Functional requirements (what the system must do)
- Non-functional requirements (performance, security, scalability)
- Out of scope (explicit exclusions)
- Assumptions we're relying on

Don't write the design yet. Confirm your understanding of the requirements first.
Flag anything ambiguous or missing before we continue.
Step 1 of 4 — Campaign Brief Chain
I need to develop a full marketing campaign brief for: [campaign name / product launch]
Context: [product, target audience, budget range, timeline]
Goal: [what conversion or awareness outcome we want]

Step 1 — AUDIENCE AND INSIGHT
Before writing any creative:
- Define the target audience segment precisely (demographics + psychographics)
- State the core insight: the one truth about this audience that our campaign must be built on
- Identify the primary competitor message we're differentiating from
- State the single most important thing we want the audience to think/feel/do

Don't write headlines or copy yet. Validate the strategic foundation first.
Step 1 of 4 — Code Review Report Chain
[Upload code / paste code]

I need to produce a structured code review report for: [PR title or feature name]
Reviewer context: [your role, relationship to this code, standards it should meet]

Step 1 — INVENTORY
Before commenting on quality:
1. What does this code do? (2-sentence functional summary)
2. List all files/modules changed and their purpose
3. Identify the entry points and main execution paths
4. Flag anything that requires domain knowledge to understand

Don't assess quality yet — ensure we both have a shared understanding of what the code is doing first.
🔗 Exercise 4 — Run a 4-Step Chain

Produce a Complex Document Using Multi-Step Prompting

Choose a real deliverable you need this week:

  • Engineer: Technical design doc for a feature currently in planning
  • Manager: Team retrospective report with insights and action items
  • Analyst: Competitive analysis of a tool or vendor your team is evaluating
  • Step 1: Frame the deliverable, confirm scope before writing begins
  • Step 2: Build the analytical foundation (research / requirements / analysis)
  • Step 3: Draft the core sections — review and refine each
  • Step 4: Ask Claude to assemble the final artifact with professional formatting

A single-shot prompt asks Claude to simultaneously understand the problem, structure the analysis, write all sections, and format professionally — with no correction points. Chaining gives you 4 correction opportunities. Each step produces a checkpoint where you redirect before errors compound.

The typical time investment: 30–45 minutes of conversation vs. 3–5 hours of manual work. The quality difference: the chained output has been reviewed and corrected at each stage — it's structurally sound by the time it's assembled.

⚡ You Can Now…

  • Break any complex deliverable into a validated step-by-step chain
  • Correct errors at each stage before they compound into the final output
  • Produce professional, publication-ready documents in a single conversation

🔌 MCP in Daily Workflows

MCP (Model Context Protocol) is an open standard that lets Claude connect directly to external tools and services — Notion, Google Drive, Slack, GitHub, and more. Instead of switching tabs to look something up, Claude can read and write to your tools in real time, inside the conversation.

🔌
MCP Changes the Workflow Entirely

Without MCP: copy content from Notion → paste into Claude → copy response → paste back into Notion. With MCP: "Summarise my Notion page on Q3 goals and turn it into a Slack update for the team." Done in one prompt.

⚙️ How to Connect an MCP Server
1
Open Claude.ai Settings

Navigate to Settings → Integrations in your Claude.ai account

2
Browse Available Connectors

Find the service you want to connect — look for the puzzle piece icon in the tools panel

3
Authenticate

Authorise Claude to access your account — uses OAuth, no password sharing

4
Enable in a Project

Add the MCP server to specific Projects where it's relevant — keeps workspaces clean

5
Use Naturally

Just ask Claude to interact with the tool — it calls the MCP server automatically

MCP Workflow Prompts

Google Drive Workflow
Find my most recent document titled [document name or keyword] in Google Drive.

Read it and:
1. Write a 3-bullet executive summary (1 sentence each)
2. Identify the top 3 action items or open decisions in the document
3. Flag anything that looks out of date or needs updating

Then: draft a brief status update I can send to my manager, based on this document.
Keep the update to 5 sentences — professional tone, no jargon.
Gmail Workflow
Search my Gmail for the email thread with [person/company] about [topic].

From that thread:
1. Summarise what was agreed or decided
2. What is the current state — are there open commitments on either side?
3. What's the most recent message and was it responded to?

Then: draft a follow-up email from me that:
- References our last exchange specifically
- Asks for [the thing I need — a decision, update, or meeting]
- Is direct and professional — under 100 words
Slack Workflow
Search the [channel name] Slack channel for messages from the last [7 days / 2 weeks].

Produce:
1. KEY DECISIONS: Any decisions made or agreed in this channel
2. OPEN THREADS: Conversations where a decision or action is still pending
3. MY ACTION ITEMS: Anything directed at me that I haven't responded to
4. TEAM BLOCKERS: Issues raised that haven't been resolved

Then: draft a channel summary message I can post to bring the whole team up to speed.
Format: short intro + 3–5 bullet points. Professional but conversational tone.
Multi-Tool Chained Workflow
Weekly Briefing — Multi-Tool Workflow

Step 1 — Calendar: What meetings do I have this week? List them with dates and attendees.

Step 2 — Gmail: For each meeting, search for recent emails with those attendees. 
Summarise any relevant context or open items.

Step 3 — Drive: Find any preparation documents linked to these meetings.
Flag which meetings have prep material and which don't.

Step 4 — Synthesis: 
Produce my weekly briefing:
- Priority meetings (require prep or decision)

🔌 Exercise 5 — Connect and Use an MCP Server

Run Your First MCP-Powered Workflow

  • Connect at least one MCP server in Claude.ai Settings (Google Drive or Gmail recommended to start)
  • Run a simple workflow: "Find my most recent document about [project] in Drive and summarise the key decisions."
  • Follow up with a cross-tool action: "Draft an email to [team member] summarising what you found."

The shift is from "assistant that answers questions" to "assistant that does things in your tools." The first time you watch Claude read a Drive document, extract action items, and draft the follow-up email in 15 seconds, the workflow change becomes obvious.

Start small: Pick one workflow you do manually every week. Map the tools it involves. Connect those tools. Build the prompt. That one automation will save hours per month.
