Core Concept

The Right Mental Model

🧠
Think of Claude as a brilliant expert colleague — not a search engine

You wouldn't hand a consultant a single word. You'd brief them. The better your brief, the better the work.

❌ Wrong Model — Search Engine
  • Matches keywords to pages
  • Returns links, not answers
  • No memory of context
  • Can't adapt to feedback
  • You do all the thinking
✅ Right Model — Expert Collaborator
  • Understands intent, not just words
  • Generates tailored original answers
  • Remembers full conversation
  • Adapts based on your feedback
  • Synthesises and reasons with you

3 Mental Models — Pick Yours

🎭 Expert Consultant — for business professionals & managers ▼

Brief Claude like you'd brief a consultant. The more specific your situation, constraints, and goal — the sharper the advice.

❌ "Give me tips for better team meetings"
✅ "My team of 6 engineers has daily standups that run 25 minutes. Decisions don't get made. I need a structured format under 12 minutes."
👨‍💻 Pair Programmer — for software engineers & developers ▼

Think out loud together. Share your code, explain what it should do, describe what's broken, and what you've tried.

❌ "Fix my Spring Boot service"
✅ "My Spring Boot controller returns 200 but the DB shows no new record. @Autowired looks correct. The method IS being hit (I see the log). Here's the code: [paste]"
📚 Personal Tutor — for students & career switchers ▼

Tell Claude your level, your goal, and how you learn. Ask for analogies from a domain you already understand.

❌ "Explain Kubernetes"
✅ "I understand Docker basics. Explain Kubernetes using a restaurant management analogy. Start from why we need it, then explain pods, nodes, and clusters."

⚠️
Key Limitation

Claude does NOT browse the internet in real time. Its knowledge has a training cutoff. Always verify current data, statistics, or rapidly changing information with authoritative sources.

The Core Framework

The RCTF Prompt Formula

Role + Context + Task + Format = Consistently Great Output

F
Format
🎭 R — Role: Tell Claude WHO to be ▼

Role is the lens Claude uses to filter its knowledge. Same question, different role = completely different output.

  • "Act as a senior Java developer with 10 years of Spring Boot experience"
  • "You are an experienced HR manager at a tech company"
  • "Act as a patient university professor great at teaching beginners"
📋 C — Context: Give the full picture ▼

Context transforms generic advice into advice for your exact situation. Include:

  • Your role and expertise level
  • Your audience (who will read the output)
  • Your constraints (time, tools, team size)
  • What you've already tried (for troubleshooting)
🎯 T — Task: Be crystal clear on the ask ▼

Use specific action verbs and define the scope precisely.

❌ "Help me with my email"
✅ "Rewrite this email to be 30% shorter, remove passive voice, make the call-to-action impossible to miss"

Action verbs: Write · Summarise · Compare · Explain · Debug · Rewrite · List · Analyse · Review · Create

📐 F — Format: Control the output shape ▼

Without a format instruction, Claude picks one. Always specify when it matters:

  • "5 bullet points, max 15 words each, start with action verbs"
  • "3-column table: Feature | Benefit | Example"
  • "Professional email format, subject line, under 150 words"
  • "Return only valid JSON. No explanation."
💡
Pro Tip

For simple tasks, Role + Task is enough. For complex or high-stakes work, use all four. RCTF is a guide, not a rigid rule.

What to Avoid

The 5 Most Common Prompting Mistakes

❌ Mistake 1 — The One-Word Prompt ▼
❌ "Python" / "Marketing" / "Write email"
✅ Add: what you want + who it's for + what outcome you need
❌ Mistake 2 — No Context ▼
❌ "How should I structure my team?"
✅ Add your team size, tech stack, experience levels, delivery goals, and constraints
❌ Mistake 3 — Accepting the First Draft ▼

The first response is a starting point. Always iterate. Try:

  • "Cut this by 40%. Keep only essential points."
  • "Point 3 is too vague — give a specific example."
  • "Rewrite to sound more human, less corporate."
❌ Mistake 4 — Vague Open-Enders ▼
❌ "Tell me everything about React"
✅ "I'm a backend Java dev. Explain the 3 React concepts I'll need most in week 1 of a React project. Skip basics I'd know from Java."
❌ Mistake 5 — Forgetting the Format ▼

No format = Claude picks one. You then spend time reformatting. Quick fixes:

  • "Format as a numbered list."
  • "Return as a professional email."
  • "Under 200 words."

What Claude doesn't know:

✅ Strong Prompt (RCTF)
Act as a professional business writer.

Context: I'm a PM at TechBuild Ltd. We promised delivery of Phase 1 to TechCorp Solutions by March 15th. Two senior devs left — pushing us to March 28th. The client relationship is strong.

Task: Write a formal but empathetic email to Sarah Chen (VP Operations). Acknowledge the delay, mention resource constraints briefly, confirm the new deadline, and offer a quick call.

Format: Subject line + 3 short paragraphs + CTA. Under 200 words.
❌ Weak Prompt
explain REST API
✅ Strong Prompt
Act as a patient senior developer great at explaining technical concepts to non-technical people.

Context: I'm explaining REST APIs to business analysts who understand websites but have never written code.

Task: Explain REST API using a restaurant analogy. Then explain GET, POST, PUT, DELETE mapped to restaurant actions.

Format: Brief intro + the analogy + a 4-row table: Method | What it does | Restaurant example. Under 250 words.

💻 Software Engineer

Understanding a Codebase You Didn't Write

Scenario: You just joined a team. You're asked to fix a bug in a Spring Boot service you've never seen.

  • Write an RCTF prompt to get a plain-English explanation of the class
  • Ask Claude to identify the most likely cause of the bug
  • Ask what tests you should run before making any change
✅ Model Prompt
Act as a senior Java developer doing an onboarding review for a new team member.

Context: I just joined a fintech startup. I need to extend PaymentNotificationProcessor — handles Stripe/PayPal webhooks, 3 years old, minimal docs. I need to add support for 'payment.refund.completed'.

Task: Looking at the code below:
1. Explain the class in plain English (2–3 sentences)
2. Where exactly should I add the new event handler?
3. Flag any fragile areas I should not touch
4. List 3 tests to run before and after my change

Format: 4 numbered sections. Specific class/method names. Plain English for architecture, technical for the rest.

📊 Manager / PM

Upgrade a Weak Prompt — Sprint Update Email

Scenario: You're a PM. Your team completed 6 of 8 sprint features. You need to brief your director and 3 stakeholders before Monday's review.

  • Write a full RCTF prompt for this email
  • Be honest about the shortfall but include a recovery plan
  • Specify a format that's easy to skim in a meeting
✅ Model Prompt
Act as a senior PM who communicates clearly with stakeholders under pressure.

Context: My team completed 6/8 sprint features. Missed: payment retry module (vendor API change) and dashboard filter (design changed requirements mid-sprint). Briefing director Meera + 3 cross-functional stakeholders before Monday's review.

Task: Write an email that covers what was delivered, what wasn't (with honest brief reasons), and the recovery plan. Pre-empt difficult questions. Show the team is in control.

Tone: Honest, calm, forward-looking. Not defensive.

Format: Subject line + 4 sections with bold headers: Delivered / Not Completed / Recovery Plan / Next Steps. Under 220 words. Easy to scan.
🎓 Student / Career Switcher

Learning a New Tech Stack Before Your First Job

Scenario: You start a backend developer role in 3 weeks. Stack: Java 17, Spring Boot 3, PostgreSQL, Docker, AWS. You have 2 hours/day to study.

  • Ask Claude for a realistic 3-week learning plan
  • Prioritise "most likely needed in week 1 at a real job"
  • Ask it to include free resources only, and add a "skip for now" section
✅ Model Prompt
Act as a senior dev and mentor who has onboarded 20+ junior developers.

Context: Fresh graduate with 2yr university Java. Starting backend dev role in 3 weeks. Stack: Java 17, Spring Boot 3, PostgreSQL, Docker, AWS. 2 hours/day available. Company builds B2B SaaS.

Task: A realistic 3-week learning plan that:
1. Prioritises "what will I definitely need in week 1 at a real job"
2. Skips things I can learn on the job
3. Fits 2 hrs/day with daily checkable goals
4. Includes free resources only (no paid courses)

Format: Week-by-week table: Day | Topic | Time | Goal | Resource. Add a "What to skip for now" section at the end.
🔄 All Roles — Iteration Practice

Improve Claude's Output in 3 Follow-Ups

Start with this prompt, then iterate using each follow-up instruction below.

Starting Prompt
Write a short LinkedIn bio for me.
I'm a software engineer with 4 years in Java and cloud. I recently became a team lead.
  • Run the prompt · read the output
  • Follow-up 1: "More confident. Start with a strong action statement."
  • Follow-up 2: "Trim to exactly 3 sentences."
  • Follow-up 3: "Add one line about what I'm passionate about in tech."

Each follow-up refines the output without losing previous improvements. Claude never starts from scratch — it builds on the last version. This is iterative prompting. The final result after 3 passes will be dramatically better than the first draft.
