🐛 Exercise 2 — Find the Root Cause

Debug This Case-Sensitivity Bug

Java — OrderService.java
public BigDecimal calculateDiscount(List<OrderItem> items, String promoCode) {
    BigDecimal total = items.stream()
        .map(item -> item.getPrice().multiply(BigDecimal.valueOf(item.getQuantity())))
        .reduce(BigDecimal.ZERO, BigDecimal::add);
    if (promoCode != null) {
        if (promoCode.equals("SAVE10"))
            return total.multiply(BigDecimal.valueOf(0.10));
        else if (promoCode.equals("SAVE20"))
            return total.multiply(BigDecimal.valueOf(0.20));
    }
    return BigDecimal.ZERO;
}
// Input: total = ₹1,300 | promoCode = "save10"
// Expected: ₹130 discount  |  Actual: ₹0
  • Use the Logic Bug prompt — walk Claude through the specific inputs
  • Ask: "What class of inputs would trigger this bug in production?"
  • Ask: "Give me the minimal fix AND the JUnit 5 test that catches it"

Bug: promoCode.equals("SAVE10") is case-sensitive. "save10" returns no match → BigDecimal.ZERO.

Minimal fix: Change to promoCode.equalsIgnoreCase("SAVE10") — or better: normalise at entry with promoCode.trim().toUpperCase() before comparisons.

Test that catches it: Pass "save10" and assert the discount equals ₹130.00.

⚡ You Can Now…

  • Get root cause, not just a patch — by giving Claude the full context
  • Every debug session ends with the test that would have prevented the bug

🔧 Refactoring & Cleaning Code

⚠️
Critical Refactoring Rule

Always tell Claude explicitly: "Preserve all existing behaviour — only improve structure." Without this, Claude may inadvertently change logic that other systems depend on.

Refactoring Prompt
PRESERVE all existing behaviour. IMPROVE structure only.
If unsure whether a change alters behaviour — flag it before doing it.

1. Identify code smells (magic numbers, God methods, deep nesting, unclear names)
2. For each: explain the problem + show the refactored version
3. Rename unclear variables/methods (show old → new)
4. Extract methods over 20 lines into single-responsibility methods
5. Replace raw loops with Streams where clarity improves

Do NOT change:
- Public method signatures
- DB / external API calls (flag these instead)

Test Generation Prompt
Framework: JUnit 5 + Mockito | Target: 80%+ branch coverage

For each public method, test:
- Happy path (standard valid input)
- Edge cases (empty, zero, boundary)
- Error paths (null input, invalid values, exceptions)
- Side effects (Mockito.verify for mocked dependencies)

Test naming: should_[expected]_when_[condition]
Structure: group by method using @Nested
Comment above each: "// Prevents: [what bug this catches]"

SOLID Review Prompt
Review for SOLID violations:
S — Single Responsibility (one reason to change?)
O — Open/Closed (add behaviour without modifying existing?)
L — Liskov Substitution (subclasses substitutable for base?)
I — Interface Segregation (interfaces too large?)
D — Dependency Inversion (high-level depends on abstractions?)

For each violation: quote it, explain the principle, show a fix.
Rate overall: Well-designed / Has issues / Needs significant rework

🔧 Exercise 3 — Spot the Smells First

List Code Smells Before Running Claude — Then Compare

Java — ReportService.java (needs refactoring)
public String generateReport(List<Transaction> txns, String type, boolean inc) {
    StringBuilder sb = new StringBuilder();
    double total = 0;
    int count = 0;
    for (Transaction t : txns) {
        if (t.getStatus().equals("COMPLETED")) {
            if (type.equals("MONTHLY")) {
                if (t.getDate().getMonth() == LocalDate.now().getMonth()) {
                    total += t.getAmount(); count++;
                    if (inc) { sb.append(t.getId()).append(",").append(t.getAmount()).append("\n"); }
                }
            } else if (type.equals("WEEKLY")) {
                if (t.getDate().isAfter(LocalDate.now().minusDays(7))) {
                    total += t.getAmount(); count++;
                    if (inc) { sb.append(t.getId()).append(",").append(t.getAmount()).append("\n"); }
                }
            }
        }
    }
    return "Total: " + total + ", Count: " + count + (inc ? "\n" + sb : "");
}
  • List every code smell you can spot before prompting
  • Run the Refactoring prompt — compare your list to Claude's output
  • Follow up: "Generate JUnit 5 tests for the refactored version"

8 smells: (1) God method — filters, aggregates, AND formats. (2) Magic strings "COMPLETED", "MONTHLY", "WEEKLY" — use enums. (3) Deep nesting — 4 levels. (4) Unclear names: inc, sb, t, txns. (5) Duplicated logic — total/count/sb block repeated. (6) Wrong type — double for financial amounts (should be BigDecimal). (7) Hard-coded date logic — not injectable, untestable. (8) Return type mixes summary and detail.

🤖 Claude Code — The Agentic Coding Assistant

⚠️
Critical Distinction

Topics 1–5 used Claude in the chat interface — you paste code, Claude responds with text. Claude Code is fundamentally different: it runs in your terminal, reads your actual repository files, makes multi-file edits, and runs commands. It is an agent, not a chatbot.

What Claude Code Is

🖥️
Terminal-Based

Runs from your command line inside your project. Integrates with your real dev environment and git workflow.

📁
Reads Your Files

Navigates your repo, reads multiple files, understands context from the whole codebase — not just what you paste.

✏️
Edits Autonomously

Makes multi-file changes, creates new files, runs commands — all while showing you each step before proceeding.

🔁
Multi-Step Reasoning

Plans before acting, shows its reasoning, asks questions when uncertain. You can interrupt and redirect at any point.

Installation

Terminal — Install & Start
# Install globally (requires Node.js 18+)
npm install -g @anthropic-ai/claude-code

# Navigate to your project and start
cd /path/to/your/project
claude

# Start simple — then escalate
> Explain the structure of this project in 3 sentences.
> Find the most complex method and explain why it's complex.
> Refactor it — show me the plan BEFORE making any changes.

The Safety-First Workflow

1
Give a High-Level Task

State what you want in plain English. Include constraints: "don't change public interfaces", "preserve backward compatibility".

2
Read the Plan — Before Approving

Claude Code shows its plan before touching files. Read every line. Correct anything that looks wrong before you approve.

3
Watch the Execution

Every file read and change shown incrementally. You can interrupt at any point by pressing Escape.

4
Review with Git Diff

Always run git diff before accepting. Read every changed line. If you don't understand a change — ask Claude Code to explain it.

5
Run Tests & Commit

Run your full test suite. Feed any failures back to Claude Code for a fix. Never commit without passing tests.

🔐
The Golden Rule — Never Skip the Diff

Claude Code is usually correct. It is not infallible. Every change is a proposal. Always read the git diff before accepting or committing. Never use Claude Code without version control.

🔌 MCP — Model Context Protocol

MCP connects Claude to your real tools — GitHub, databases, file systems, Slack, internal APIs. Without MCP, Claude knows only what you paste. With MCP, Claude reaches into your actual environment.

🔌 The USB-C Analogy: USB-C is one standard port for power, data, and video. MCP is one standard protocol that connects Claude to GitHub, Postgres, Slack, Jira — or any internal tool you build a server for. One protocol, unlimited integrations.

🖥️
MCP Server

A small Node.js or Python process that wraps a tool's capabilities. Exposes them to Claude via a standard interface.

🤖
MCP Client (Claude)

Claude Code or claude.ai discovers which tools are available and calls them when needed to complete your task.

⛓️
Tool Chaining

Read a GitHub issue → find the related code → write a fix → open a PR. One prompt, multi-tool execution.

GitHub MCP Prompts
> List all open issues labeled "bug". For each: summarise the

> Write a SQL query: customers with 3+ orders in the last 30 days
